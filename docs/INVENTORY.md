# File inventory

Every file tracked by git, described in one or two sentences that stand on
their own. A reader should not need any other document to understand what a
file is for.

**Kinds:** `module` = Python code under `src/`, imported by other files;
`script` = Python under `scripts/`, run by hand; `test` = pytest file under
`tests/`; `config` = read by a tool; `docs` = prose; `notebook` = exploration;
`figure` = image for reports; `run output` = written by a script (committed in
error, pending cleanup).

| Path | Kind | Description |
|---|---|---|
| `.dockerignore` | config | Excludes from the Docker build context: version control (`.git`, `.gitignore`); virtual environment and Python caches (`.venv`, `__pycache__/`, `*.pyc`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `*.egg-info/`); data and results (`data/`, `runs/`, `reports/`, `notebooks/`, `*.npy`, `*.pt`, `*.pth`, `*.nii.gz`); secrets (`.env`, `.env.*`); and things the tool image does not need (`docs/`, `tests/`, `src/femuralabs/toolkit/training/`). Without this file, the entire virtual environment — roughly two gigabytes including PyTorch — is sent to the Docker daemon on every build. The size of the exclusion is visible in the `transferring context` line of any build output: a few tens of kB with the file, roughly two thousand times larger without. |
| `.gitignore` | config | Excludes `.venv/`, `__pycache__/`, `*.pyc` and the contents of `data/` (with `data/.gitkeep` in git to preserve the folder). Files under `runs/`, `reports/` and `notebooks/` were committed before this rule applied and remain tracked; see D006 in `DECISIONS.md`. |
| `AGENTS.md` | docs | Instructions for any AI agent or new contributor: repository layout, the rule against duplicate functions, the documentation that must be kept accurate, the working protocol, commit message format, and the constraints that protect reproducibility and privacy. Start here. |
| `Dockerfile` | config | Builds the `toolkit-hello` image. `python:3.12-slim` base, three `ENV` variables (`PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED`, `PYTHONPATH=/app/src`), then install `requirements-tool.txt`, then `useradd student`, then `COPY src/`. `USER student` switches to the unprivileged account for everything below it and for the running container, so code is readable but not writable and a compromised program cannot rewrite itself. `EXPOSE 8000` documents the port (publishing is done by `-p`). `CMD ["python", "-m", "femuralabs.toolkit.cli"]` is the default; any word after the image name on `docker run` replaces it entirely, which is how `python -m femuralabs.toolkit.service.serve` starts the service without a second image. `training/` is excluded by `.dockerignore` (needs `torch`, not installed here). At run time, host folders are mounted at `/data` (read-only, for inputs) and
`/output` (writable, for results); see D016. |
| `README.md` | docs | Public entry point. One paragraph of purpose, a quick-start block that a stranger can follow, the test command, and a limits block that states clearly that the project is a research prototype and not a tool for clinical decisions. Maintainer detail belongs in `docs/`, not here. |
| `conftest.py` | config | Prepends `src/` to `sys.path` so pytest can `import femuralabs` without a `PYTHONPATH` prefix. Placed at project root so it applies to every file under `tests/`. |
| `data/.gitkeep` | placeholder | Keeps the empty `data/` folder in git while excluding everything inside it. The folder holds downloaded arrays and generated test data; nothing in it is committed. |
| `docs/DECISIONS.md` | docs | Every design choice in this repository that could reasonably have been made differently, with the alternative that was rejected and the reason. Read an entry before changing the behaviour it describes. New entries go at the top. |
| `docs/INVENTORY.md` | docs | This file. Describes every tracked path. Read before adding a file, so that an existing one is not duplicated. |
| `docs/RUNBOOK.md` | docs | Every command that has been run on this workstation, with the expected output, what the step proves, and what a failure means. Read before running anything for the first time. |
| `notebooks/01_numpy_images.ipynb` | notebook | Exploration: building, slicing, normalising, and windowing a small volume interactively. No functions are defined here; every call is into `femuralabs.toolkit`. Kept as a record of how the toolkit's behaviour was checked by hand. |
| `notebooks/02_pytorch_loop.ipynb` | notebook | Exploration: running the training loop interactively and inspecting per-epoch values. Same rule as the first notebook: calls into modules, no definitions. |
| `reports/hand_convolution.jpg` | figure | Photograph of the hand-worked 5×5 image convolution. Kept as evidence that the reference `conv2d` result was computed by hand before the loop was trusted. |
| `reports/histogram.png` | figure | Histogram of a CT-like intensity array, saved at 200 dpi for reports. Regenerated by `notebooks/01_numpy_images.ipynb`. |
| `reports/notebook_check.png` | figure | Snapshot of the notebook run used to verify that every cell executes cleanly after a kernel restart. |
| `reports/run_a_curves.png`, `reports/run_b_curves.png` | figure | Training and validation loss curves from two training runs, both seeded with the same value. The two curves being nearly identical is the reproducibility check. |
| `reports/window_curve.png` | figure | Plot of the linear intensity window over a range of Hounsfield units, showing clipping below `L − W/2` and above `L + W/2`. |
| `requirements-tool.txt` | config | The pinned `numpy` version that the tool container installs. Kept separate from `requirements.txt` because that file pulls PyTorch from the CUDA wheel index and would multiply the image size. Update together with `requirements.txt` when numpy's version changes. |
| `requirements.txt` | config | The development environment: PyTorch (CUDA wheel from the PyTorch index), torchvision, numpy, matplotlib, pytest. Used by the training scripts, not by the tool container. |
| `runs/run_a/config.json`, `runs/run_a/metrics.csv` | run output | Command-line settings and per-epoch metrics from one training run. Committed before the `.gitignore` rule existed; see D006 in `DECISIONS.md`. |
| `runs/run_b/config.json`, `runs/run_b/metrics.csv` | run output | Settings and metrics from a second run with an identical seed. Compared with `run_a` by `scripts/compare_runs.py` to demonstrate reproducibility. Same tracking situation as `run_a`. |
| `scripts/api_demo.py` | script | (none) → three printed request lines | Starts the geometry service in a background thread on a random free port and calls `/health`, `/info` and a missing path with `urllib`. The 404 arrives as an exception, which the script catches and treats as a reply. Demonstrates the service without needing a container. |
| `scripts/check_tree.py` | script | Verifies that every file the project claims to contain exists on disk. Exits non-zero if a required path is missing. Its `REQUIRED` list is kept in sync with `docs/INVENTORY.md`; run it before every commit. |
| `scripts/compare_runs.py` | script | Reads two `metrics.csv` files and prints the largest absolute difference in validation loss. Used to confirm that two runs with the same seed produced nearly identical numbers; the expected value is exactly zero on CPU and a value in the fifth or sixth decimal on GPU. |
| `scripts/hello_pipeline.py` | script | Prints shape, spacing and dtype of a synthetic volume. Imports `make_volume` from `femuralabs.toolkit.volume_info`; it does not define the function itself. Run with `PYTHONPATH=src` outside the container, and with no prefix inside the container because the image sets `PYTHONPATH=/app/src`. |
| `scripts/train_small_cnn.py` | script | Trains `SmallCNN` on MNIST for a given number of epochs and a given seed, saving per-run configuration, metrics and best checkpoint under `runs/<name>/`, and a learning-curve PNG under `reports/`. Every step is a call into `femuralabs.toolkit.training.train_utils` or `femuralabs.toolkit.training.model`. |
| `src/femuralabs/__init__.py` | module | Package marker. Empty. |
| `src/femuralabs/toolkit/__init__.py` | module | Package marker. Empty. |
| `src/femuralabs/toolkit/arrays.py` | module | NumPy array helpers. `zscore_batch` normalises each volume in a `(B, Z, Y, X)` batch to mean zero and standard deviation one. `window_to_uint8` maps Hounsfield units to 0–255 through a linear window for display only. `conv2d` is a slow reference convolution with stride and padding, kept because it is easy to check by hand against `tests/test_arrays.py`. |
| `src/femuralabs/toolkit/cli.py` | module | Command-line entry point for volume geometry. Accepts `--file` (a saved `.npy`), `--shape` and `--spacing` (for a synthetic volume), and `--out DIR`. Prints four lines — shape, spacing, dtype, extent. When `--out DIR` is given, also calls `report.write_info` and prints `wrote: …` with the returned path. A separate entry point from `summary`, because `summary` answers a statistics question with a checked output string; see D003 in `DECISIONS.md`. |
| `src/femuralabs/toolkit/summary.py` | module | Reads a `.npy` array and reports shape, dtype, min, max and mean. Exposed both as functions (`summarise`, `load_and_summarise`) and as a command line (`python -m femuralabs.toolkit.summary path.npy`). Rejects non-`.npy` suffixes and missing files with a one-line message rather than a traceback, so the tool can be chained in scripts. |
| `src/femuralabs/toolkit/volume_info.py` | module | `make_volume` returns a zero `float32` array of shape `(z, y, x)` and its spacing in millimetres. `describe` returns shape, spacing, dtype, and the physical extent in millimetres (voxels × spacing). Both are pure functions with defaults that match the small synthetic volume used by `scripts/hello_pipeline.py`. |
| `src/femuralabs/toolkit/service/__init__.py` | module | Package marker. Empty. |
| `src/femuralabs/toolkit/service/api.py` | module | HTTP handler | Translates `routes.route`'s `(status, dict)` return into a wire response. `do_GET` is called by `http.server` for each GET; `send_response` → `send_header` → `end_headers` → `wfile.write` is the correct order. `Content-Type: application/json` is set explicitly; see D007. `log_message` is silenced to keep `docker logs` clean. |
| `src/femuralabs/toolkit/service/routes.py` | module | request path → `(status, body)` | The three branches of the geometry service: `/health` → `{"status": "ok"}`, `/info` → the four-key geometry dictionary, anything else → 404. Pure function, no network, no files. Testable without starting a server; see `tests/test_routes.py`. Tuple fields are converted to lists so the returned dict is JSON-ready as-is. |
| `src/femuralabs/toolkit/service/serve.py` | module | `PORT` environment variable → running server | Binds `0.0.0.0:PORT` and calls `serve_forever` until `Ctrl+C`. `0.0.0.0` (not `127.0.0.1`) is required so a port published by Docker can reach the server. Default port 8000. |
| `src/femuralabs/toolkit/training/__init__.py` | module | Package marker. Empty. |
| `src/femuralabs/toolkit/training/model.py` | module | `SmallCNN`: two convolution blocks with max-pooling and a single linear layer, for 28×28 grayscale images with ten classes. Exactly 9098 trainable parameters, checked by `train_utils.count_parameters`. |
| `src/femuralabs/toolkit/training/train_utils.py` | module | Training utilities. `set_seed` seeds Python, NumPy and PyTorch (including every CUDA device) and disables cuDNN benchmark mode so results are reproducible. `get_device`, `count_parameters`, `save_checkpoint`, `load_checkpoint`, `append_row`, `save_config`, `read_metrics`, `plot_curves`, `max_abs_diff`, `train_one_epoch`, `evaluate_with_accuracy` complete the set. Every function returns a value; nothing prints. save_config delegates to io.save_json rather than reimplementing the parent-folder creation and the write. |
| `tests/test_arrays.py` | test | Verifies `zscore_batch`, `window_to_uint8` and `conv2d` against hand-computed values, including a fully hand-worked 5×5 convolution on a fixed input. |
| `tests/test_routes.py` | test | — → pass/fail | Covers the three branches of `routes.route` without a server. Pins the health status, the full geometry body, and the 404 for unknown paths. |
| `tests/test_train_utils.py` | test | Verifies that two calls to `set_seed` followed by a random draw produce identical tensors, and that a checkpoint written by `save_checkpoint` round-trips through `load_checkpoint` with weights preserved. |
| `scripts/clean_check.sh` | script | (none) → pass/fail per stage | Clones the repository into a temporary folder and runs four checks there: `pytest -q`, `python -m femuralabs.toolkit.cli`, `docker build`, `docker run`. Asserts that the CLI output contains `shape (z, y, x): (4, 6, 6)` in both the host and the container. Cleans up the temporary folder with `trap … EXIT`. Must be run from an activated virtual environment so `pytest` and `python` resolve to the development interpreter. Proves that committed files alone reproduce the output; an uncommitted or ignored file that the build relies on fails here even when the local working tree passed. |
| `tests/test_cli.py` | test | — → pass/fail | Runs the CLI as a subprocess with `sys.executable -m femuralabs.toolkit.cli`, setting `PYTHONPATH=src` in the subprocess environment, and asserts on the printed lines. Proves the invocation path (module entry point, `if __name__ == "__main__":`, `raise SystemExit(main())`), which the in-process tests in `test_routes.py` do not. Catches a missing `__main__` guard or a wrong `-m` path; a missing `PYTHONPATH` fails here with `No module named 'femuralabs'`. |
| `src/femuralabs/toolkit/io.py` | module | `save_json(path, data, *, indent=None)` writes a dictionary to a file as JSON, creates parent folders, appends a trailing newline, and returns the written path. The single JSON-write primitive in the repository; both `training/train_utils.save_config` and `report.write_info` call it. Flat at `toolkit/` rather than under a subpackage because it is one file called from two places; it moves into a subpackage only when a second I/O helper arrives. Flat rather than under `training/` because `report.py` must import it inside the tool image, which excludes `training/` (see D011). |
| `src/femuralabs/toolkit/report.py` | module | `write_info(info, out_dir)` writes `info` to `out_dir/info.json` and returns the written path. The folder is a required parameter with no default, so a host run and a container run cannot silently disagree about where the file went. Uses `io.save_json` for the write; does not print; the caller decides what to do with the returned path. |
| `docs/FLOW.md` | docs | Cumulative record of annotated call graphs, one section per recorded point. Sections are prepended above a `<!-- INSERT HERE -->` marker and are never edited or removed, so a stale diagram remains visible as a past stage rather than silently wrong. The most recent section at the top is the current shape. Diagrams supplement the tests; they do not replace them. |
| `docs/flow/<slug>.png` | figure | The rendered PNG for one `FLOW.md` section, referenced from that section by `<img src>` so GitHub renders it inline. Committed; never hand-edited. Regenerated by `scripts/draw_flow.py`, which is host-only (requires matplotlib, not in the tool image). |
| `scripts/draw_flow.py` | script | Renders a JSON spec on stdin as a matplotlib diagram of boxes and arrows into `docs/flow/` and prepends a section to `docs/FLOW.md` above the `<!-- INSERT HERE -->` marker. The script itself never changes per recorded change; only the JSON spec passed to it changes, so a new diagram is one copy-pasted command, not a new file. Node kinds map to colours (module blue, script green, cli yellow, file white-dashed, external grey). Refuses to prepend a section whose id already exists. Host-only: depends on matplotlib, which the tool image does not install. --slug values are semantic (write-info-out-flag), not chapter or session numbers, so docs/FLOW.md is readable without external context. |
